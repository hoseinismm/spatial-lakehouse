ساختار پیاده‌سازی و راهنمای استفاده از SpatialBricks

مستندات کامل معماری پلتفرم پردازش داده‌های مکانی در مقیاس بزرگ

شرح ساختار برنامه

چارچوب SpatialBricks جهت بهبود کارایی پردازش، مدیریت و نمایه گذاری داده های مکانی در پلتفرم های پردازش توزیع شده (مانند Spark و Iceberg) طراحی شده است. معماری کلی برنامه از اجزای مختلفی شامل درگاه API، اجراکننده های پایپ لاین، مبدل های فرمت و مدیریت باکت ها تشکیل شده است.

SpatialBricks
API Core

درگاهی اصلی است که رابط کاربر با مولفه spatialBricks بوده و از طریق آن کاربر به تمام توابع مورد نیاز دسترسی پیدا می کند.

PipeLineExecutor
Executor

برای هر حالتی که کاربر درخواست ورود و ثبت اطلاعات نماید، متدهای لازم متناسب با درخواست های مختلف را در بر دارد تا عملیات ها را به ترتیب اجرا کند.

GeometryReader
Interface

حاوی زیرکلاس هایی است که متد لازم برای خواندن انواع داده مکانی (WKT, WKB, GeoJSON) را دارند و شیء ایجاد شده را به PipeLineExecutor یا AddOrUpdateIndex تحویل می دهد.

UdfRegistry
Interface

حاوی زیرکلاس هایی برای قالب بندی و رمزگشایی (Decode) از قالب داده مکانی بر حسب نوع انتخابی کاربر می باشد.

AddOrUpdateIndex
Indexing

برای نمایه گذاری جداولی است که قبلاً توسط PipeLineExecutor بدون نمایه ساخته شده اند یا بازنمایه گذاری داده های قبلی جهت افزایش دقت.

SpatialReader
Reader

مسیر داده را خوانده، ستون داده مکانی را پیدا کرده، آن را به شیء JTS تبدیل نموده و کل جدول را در قالب دیتاست اسپارک برمی گرداند.

GeometryTransformer
Transformer

تبدیل داده مکانی به یکی از سه فرمت WKB، SP یا FSP با الگوی Adapter. فرمت ها در ستون geometry همراه با زیرستون bbox_partitioning ذخیره می گردند.

BucketManager
Core Storage

مدیریت باکت مرجع، بارگذاری اسنپ شات، ایجاد اتوماتیک باکت مرجع جهانی، تخمین زیرباکت های جدید و محاسبه مرزها (computeBucketBorders).

BboxIndexing
Distributed Index

ارسال نسخه باکت مرجع به کل خوشه ها و استفاده از UDF اختصاصی FindBucket برای محاسبه مستقل مقادیر bbox_partitioning در هر خوشه.

BucketService
Service

تصحیح اطلاعات باکت بر اساس فراداده پارتیشن های جدول موجود جهت جلوگیری از انباشت خطاها.

TableWriter
Writer

بررسی وجود جدول، تطابق اسکیمای دیتافریم با اسکیمای جدول و ذخیره اتمیک جدول و فایل باکت مرجع مجزا.

📌 نکته مهم در ذخیره سازی دیتافریم

در صورتی که کاربر تقاضای نمایه گذاری داده را نموده باشد، به دلیل وجود سه دستور اکشن (Action) و جلوگیری از تکرار عملیات تبدیل، دیتافریم مورد نظر به صورت کش (Cache) ذخیره می گردد.

پیش نیازها و نسخه های نیازمند پشتیبانی

این چارچوب با نسخه های زیر توسعه و آزمایش شده است:

Java JDK 17
Apache Spark 3.5.6
Scala 2.13
Apache Iceberg 1.9.2

Apache Maven 3.9+

⚠️ استفاده از نسخه های متفاوت ممکن است به دلیل تغییر در APIها، وابستگی ها یا سازگاری کتابخانه ها باعث بروز خطا شود.

مراحل نصب و آماده سازی پروژه

  1. دریافت مخزن پروژه از گیتهاب: 
    git clone https://github.com/hoseinismm/spatialbricks.git
  2. پروژه را در محیط IntelliJ IDEA باز کرده و فایل pom.xml را به Maven اضافه نمایید.
  3. در بخش Maven Lifecycle، ابتدا دستور clean و سپس install را اجرا نمایید.
  4. برای استفاده از کتابخانه در پروژه های دیگر، وابستگی زیر را به pom.xml پروژه خود اضافه کنید: 
    <dependency>
    <groupId>ir.smh</groupId>
    <artifactId>spatialbricks</artifactId>
    <version>1.0-SNAPSHOT</version>
</dependency>
⚙️ تنظیمات VM Options برای Java 17

نمونه کدهای کاربردی و نحوه استفاده

۱. تنظیمات پیکربندی SparkSession

نمونه تنظیمات اسپارک آزمایش شده با چارچوب همراه با پیکربندی های Iceberg و Sedona:

SparkSession spark = SparkSession.builder()
    .appName("Spatial-Lakehouse-Writer")
    // MEMORY
    .config("spark.driver.memory", "12g")
    .config("spark.driver.maxResultSize", "4g")
    .config("spark.executor.memory", "8g")
    .config("spark.memory.fraction", "0.8")
    .config("spark.memory.storageFraction", "0.3")
    // OFFHEAP
    .config("spark.memory.offHeap.enabled", "true")
    .config("spark.memory.offHeap.size", "2g")
    // PERFORMANCE
    .config("spark.sql.shuffle.partitions", "50")
    .config("spark.default.parallelism", "50")
    .config("spark.sql.autoBroadcastJoinThreshold", "-1")
    .config("spark.sql.files.maxPartitionBytes", "32m")
    .config("spark.sql.parquet.blockSize", "32m")
    // SEDONA + ICEBERG
    .config("spark.sql.extensions",
            "org.apache.iceberg.spark.extensions.IcebergSparkSessionExtensions," +
            "org.apache.sedona.sql.SedonaSqlExtensions")
    .config("spark.sql.catalog.spark_catalog",
            "org.apache.iceberg.spark.SparkSessionCatalog")
    .config("spark.sql.catalog.spark_catalog.type", "hadoop")
    .config("spark.sql.catalog.spark_catalog.warehouse", warehousePath)
    // PACKAGES
    .config("spark.jars.packages", String.join(",", new String[]{
            "org.apache.iceberg:iceberg-spark-runtime-3.5_2.13:1.9.2",
            "org.apache.sedona:sedona-spark-shaded-3.5_2.13:1.7.2"
    }))
    .master("local[4]")
    .getOrCreate();

۲. مقداردهی اولیه و نوشتن ساده داده

import ir.smh.spatialbricks.api.SpatialBricks;
import ir.smh.spatialbricks.api.InputFormat;
import ir.smh.spatialbricks.api.GeometryFormat;

// مقداردهی اولیه
SpatialBricks sb = new SpatialBricks(spark, InputFormat.GEOJSON, GeometryFormat.FSP);

// نوشتن داده در جدول nyc.taxi
sb.write("nyc", "taxi", "datasets/taxi.geojson");

۳. نوشتن داده همراه با نمایه گذاری مکانی (Write With Index)

sb.writeWithIndex(
    "nyc", 
    "taxi", 
    "datasets/taxi.geojson", 
    1500000,  // driverRows: تعداد رکورد محاسباتی درایور
    131072   // maxPartitionSize: آستانه مرزی تعداد رکوردهای پارتیشن
);

۴. سایر روش های بارگذاری و بازنمایه گذاری

// نمایه گذاری ردیف های جدید که قبلا وارد شده اند اما کلید پارتیشن آن ها Null است
sb.addIndexToNewRows("nyc", "taxi", 1500000, 131072);

// استفاده مستقیم از Dataset اسپارک به عنوان ورودی
Dataset<Row> df = spark.read().parquet("datasets/taxi.geojson");
sb.writeWithIndex("nyc", "taxi", df, 1500000, 131072);

// بارگذاری از فایل Parquet دارای دو ستون طول و عرض جغرافیایی (Latitude / Longitude)
sb.writeWithIndex("nyc", "taxi", "datasets/taxi.parquet", "Start_Lon", "Start_Lat", 1500000, 131072);

// بازسازی کامل نمایه برای کل دیتاست (Rebuild Index)
sb.rebuildIndex("nyc", "taxi", 1500000, 131072);

۵. رمزگشایی (Decode) و اجرای پرس وجوهای پیشرفته Sedona

// خواندن از Iceberg و رمزگشایی داده به شیء JTS
Dataset<Row> t = spark.read()
    .format("iceberg")
    .load(fullName)
    .withColumn("geom", expr("decodeGeometry(geometry)"));

// در صورت عدم تعریف شیء SpatialBricks اولیه، ثبت UDF به صورت دستی:
UDFRegistry<?,?> udfRegistry = new FlattenSpatialParquet(spark);
udfRegistry.registerDecode();

۶. بهینه سازی پرس وجو با استفاده از فیلتر مرزی BBox

با افزودن شرط مرزی محدوده مکانی به پرس وجو، اسپارک با استفاده از خاصیت Lazy Evaluation و فراداده پارتیشن ها، ابتدا پارتیشن های نامرتبط را حذف کرده و سرعت اجرا را به شدت افزایش می دهد:

SELECT SUM(ST_AreaSpheroid(geom)) AS total_area
FROM polygons, iran
WHERE ST_Within(geom, iran.geom)
  AND geometry.bbox_partitioning.min_x < 63.5
  AND geometry.bbox_partitioning.min_y < 40.8
  AND geometry.bbox_partitioning.max_x > 44.0
  AND geometry.bbox_partitioning.max_y > 25.0;

فرمت فایلهای ورودی مجاز

فایل ورودی تعریف شده برای نرم افزار باید یکی از سه نوع زیر باشد:

  • CSV
  • Parquet
  • JSON (حتماً از نوع ndjson یعنی هر رکورد در یک سطر مجزا)
💡 تبدیل JSON معمولی به NDJSON

در صورتی که فایل JSON استاندارد (غیر ndjson) دارید، می توانید با استفاده از ابزار کمکی ConvertGeoJsonStreaming در پوشه utilities پروژه، فایل را به فرمت ndjson تبدیل نمایید.
